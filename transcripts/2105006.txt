AI:
Catch them at the embedding boundary, before any persistence. I added a matrix
validation step that converts the result to contiguous float32 and checks:

- the output is two-dimensional;
- the row count exactly matches the number of chunks;
- the column count equals `embed.dim`;
- every value is finite; and
- no vector is zero when normalization is enabled.

The vectors are then L2-normalized row by row. This makes FAISS inner product
equivalent to cosine similarity for normalized data. Empty input returns a
correct `(0, dimension)` float32 array. Model loading remains lazy, and tests
inject a deterministic encoder so CI does not download BGE-M3. This moves the
failure to the exact source of the invalid data and gives a useful message
instead of a later FAISS assertion or bad score.

REFLECTION

WHAT I ACCEPTED
---------------

I accepted BGE-M3 as the production embedding model because the Kaggle
comparison measured Hit@5 0.5 against 0.0 for the lightweight multilingual
MiniLM baseline on the fixed Bangla query set. I accepted L2-normalized
FAISS FlatIP because exact search is simple, deterministic, and appropriate for
1,910 chunks. At this corpus size, an approximate index would add tuning and
failure modes without a demonstrated benefit.

I accepted rule-aware chunks even though they tied the fixed baseline at Hit@5
0.5. The choice is based on a declared tie-break and structural usefulness,
not a false accuracy improvement. Grammar definitions, numbered rules,
examples, tables, and page citations remain together, which will support
grounded answers and reranking in A3.

I accepted strict validation and fail-closed loading. A vector-to-metadata row
mismatch can produce a fluent answer with the wrong citation, which is worse
than refusing to load. Shape, dimension, finite-value, zero-vector, schema,
count, and dimension checks make those failures visible at their source.

WHAT I CHANGED
--------------

I changed the index code from unimplemented stubs to a lazy embedding path and
a persisted FAISS/metadata pair. I changed the build script from a potentially
duplicated Make invocation to one fixed pipeline call. I also changed the
security workflow after tracing the red job to the uv 0.4.4 command interface;
the correction preserved Bandit's scan rather than suppressing B101.

The failure cases I investigated changed my implementation choices. A wrong-dimension,
NaN, or zero embedding is now rejected before FAISS. Corrupt JSON or a vector
count mismatch is rejected during reload. A path inside Kaggle input is
rejected before a write attempt. These cases became explicit behavior rather
than assumptions.

I rejected downloading BGE-M3 during ordinary unit tests. Dependency injection
keeps tests fast and deterministic while Kaggle provides the real-model
evidence. I rejected storing only FAISS row numbers without complete Chunk
metadata because that would break page-level citations after restart.

success. Its text is semantically correct, but the expected historical page
